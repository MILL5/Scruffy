# Scruffy code review — November 9, 2026

Scope: everything in `src/`, `tests/`, `scripts/`, `docs/` and `README.md` (about 1,500 lines of Swift). Baseline: `swift test` passes all 25 tests, and `swift build` finishes with no warnings.

The safety design holds up well. Every file is checked again right before it moves (fingerprint plus a fresh full hash for duplicates), symlinked ancestors and hard links are rejected, a protected original can't be selected, CacheDelete is isolated in an unprivileged helper with a service allowlist and alarms, and the admin script is built only from enum values. Most of the findings below are about usability, efficiency and keeping the docs in sync, not about data loss.

## High priority

1. **No bulk selection, so the cache categories are impractical.** Every file needs its own checkbox click ([ScruffyApp.swift:243](../../src/Scruffy/ScruffyApp.swift#L243)), and the only bulk action is "Clear selection" ([ScruffyApp.swift:235](../../src/Scruffy/ScruffyApp.swift#L235)). A Chrome or npm cache often holds thousands of files. Add "Select all in this view" (skip protected originals, respect the filter, show a count). It's still explicit, so it doesn't break the "nothing auto-selected" promise.

2. **A failed move leaves a fake entry in Recovery history.** [TrashService.swift:52-55](../../src/CleanupCore/TrashService.swift#L52-L55) saves the intent record before calling `trashItem`. If the move throws (a locked `uchg` file, permission denied, a missing Trash), the catch at [line 65](../../src/CleanupCore/TrashService.swift#L65) breaks out without removing that record. The journal then lists a file that never moved, with Restore permanently disabled. Fix: on a move error, remove the last record and save the journal again. Keep `trashed == nil` records only for real interruptions. Add a test where `moveToTrash` throws.

3. **Cleanup reads each duplicate copy and its original four times, with no progress or cancel.** `validateSelection` hashes the original and the copy in full. `clean` calls it once for the whole batch ([TrashService.swift:41](../../src/CleanupCore/TrashService.swift#L41)) and again for each item ([line 50](../../src/CleanupCore/TrashService.swift#L50)), at [Scanner.swift:396](../../src/CleanupCore/Scanner.swift#L396). Removing 10 copies of a 4 GB file reads about 160 GB. Options:
   - Keep the fresh per-item hash, which is the safety-critical one.
   - In the whole-batch pass, check fingerprints only.
   - Hash each original once per batch, and again only if its fingerprint changed.
   - Show progress for each item and add a Cancel button (`clean` already checks for cancellation).

4. **The recovery journal grows forever and is rewritten in full twice per file.** The `save(history)` calls at [TrashService.swift:54 and 60](../../src/CleanupCore/TrashService.swift#L54-L60) encode the whole history each time, so cleanup I/O grows quadratically. Entries whose Trash item is gone are never pruned, so the history list keeps growing with dead rows. Options:
   - Prune records whose `trashed` file no longer exists when loading.
   - Cap the history by age or count.
   - Write once per batch, keeping a per-item write only for the intent record.

5. **The protected original is always the oldest copy, and the user can't change it.** Choosing by oldest `mtime` ([Scanner.swift:364-369](../../src/CleanupCore/Scanner.swift#L364-L369)) often protects the copy in `~/Downloads` and puts the copy in `~/Documents` up for removal. Prefer an original outside Downloads, and add a "Keep this one instead" action. The validation already finds the original through `keeper`, so swapping the flag is enough.

6. **The project has no source control and no repo `AGENTS.md`.** This app moves user files to Trash, so put it under git before changing safety code. Add a short `AGENTS.md` covering the safety invariants: fail closed, nothing auto-selected, fixed admin command, CacheDelete allowlist.

## Medium priority

7. **One shared `target` value drives both destructive actions.** The system-purge picker ([PurgeableView.swift:228](../../src/Scruffy/PurgeableView.swift#L228)) and the snapshot picker ([PurgeableView.swift:147](../../src/Scruffy/PurgeableView.swift#L147)) both bind `model.target`, so changing one silently changes the other. Use two separate values.

8. **Firefox Developer Edition and Nightly don't block Firefox cache cleanup.** They use bundle IDs `org.mozilla.firefoxdeveloperedition` and `org.mozilla.nightly`, but they share `~/Library/Caches/Firefox/Profiles`. The running-browser check ([AppModel.swift:93](../../src/Scruffy/AppModel.swift#L93)) only knows `org.mozilla.firefox`. Add both IDs and a unit test for the matcher (it is currently private to the app target).

9. **The UI recomputes derived data on every render.**
   - `count(_:)`, `bytes(_:)` and `visible` each filter the full result ([AppModel.swift:29-34](../../src/Scruffy/AppModel.swift#L29-L34)). The overview calls `bytes(_:)` up to three times per category, and `visible` runs three times per render.
   - Each duplicate row filters every file to count its matches ([ScruffyApp.swift:256](../../src/Scruffy/ScruffyApp.swift#L256)).
   - All of this repeats on every progress update (every 150 ms) and every keystroke in the filter field.

   With cache results in the tens of thousands, this will stutter. Compute per-category totals and per-hash counts once in `publish(_:)`.

10. **No Full Disk Access guidance.** `~/Library/Caches/com.apple.Safari` and other locations need Full Disk Access. They currently show up only as "Could not read" notes in a collapsed list. Detect the denial and offer a button that opens Privacy & Security › Full Disk Access.

11. **The external-volume exclusion isn't enforced.** `volumeIsLocal` is true for USB disks ([Scanner.swift:136](../../src/CleanupCore/Scanner.swift#L136)), so a volume or disk image mounted inside the home folder is eligible. The README says external volumes are excluded. Fix: require `fingerprint.device` to match the home volume's `st_dev`.

12. **Storage figures depend on `tmutil`.** `report()` throws when `tmutil` can't list snapshots ([PurgeableStorage.swift:72-73](../../src/CleanupCore/PurgeableStorage.swift#L72-L73)), which also hides free space and the reclaimable estimate. Publish capacity on its own.

## Low priority

- **The large-file threshold disagrees with the displayed sizes.** It's 500 MiB (524 MB) ([Scanner.swift:293](../../src/CleanupCore/Scanner.swift#L293)), but the UI says "500 MB" and `ByteCountFormatter.file` shows decimal units. A file displayed as 510 MB won't be listed.
- **Folder choices and scan toggles reset on every launch.** Only the appearance setting is persisted.
- **Restoring one file clears the whole scan** ([AppModel.swift:116](../../src/Scruffy/AppModel.swift#L116)). That's safe but disruptive. Removing the restored path's group from the results would be enough.
- **The scan task's error paths skip the generation check** ([AppModel.swift:61-62](../../src/Scruffy/AppModel.swift#L61-L62)), so a stale scan could overwrite `status`. It's hard to trigger today because Settings is disabled while busy.
- **A reclaim can silently do nothing.** If a refresh empties the snapshot list while the confirmation sheet is open, `reclaim()` fails its guard and shows no message.
- **The confirmation sheet builds every selected row up front** ([ScruffyApp.swift:328](../../src/Scruffy/ScruffyApp.swift#L328)). Use `LazyVStack` once bulk selection exists.

## Build and packaging

- **`build-app.sh` never removes the old bundle**, so stale `Scruffy.icns` and `ScruffyBroom.icns` still ship in `dist/Scruffy.app/Contents/Resources/` (checked). Add `rm -rf "$APP"` before packaging.
- **The `Bundle.module` fallback can crash.** Image loading falls back to `Bundle.module` ([ScruffyApp.swift:43, 53](../../src/Scruffy/ScruffyApp.swift#L43)), but the script never copies the SwiftPM resource bundle. Off the build machine, that accessor calls `fatalError`. Copy `Scruffy_Scruffy.bundle`, or drop the fallback.
- **The MILL5 logo is too small for Retina.** It's 237×54 and displayed at 166×38, so it looks soft on Retina screens. Get a 2× or vector asset.
- **The app isn't ready for distribution.** Signing is ad-hoc, there's no hardened runtime and no notarization, and CacheDelete is a private API. Fine for personal use; sharing it needs Developer ID signing plus notarization.
